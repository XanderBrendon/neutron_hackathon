# Chipswap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Chipswap Neutron app — a chip editor, a ten-slot design lifecycle, a paid cross-Neutron trading protocol, a shared designer directory, and a filtered chip store — packaged as an installable `chipswap.v0.1.0.neutron`.

**Architecture:** One Neutron app package (`apps/chipswap`) with a Motoko backend module and a React tile. Inbound peer traffic arrives through `capabilities.public_ingress` (five route ids sharing one `chipswap_v1` update dispatcher); outbound peer traffic uses `capabilities.backend_calls` with a `method`-scoped install reservation. Peer *requests* are typed Candid (kernel-validated); peer *responses* are `Blob` carrying a compact `CSW1` binary wire that the caller parses with bounded, non-trapping byte arithmetic.

**Tech Stack:** Motoko (`mo:core` v2.6.0, `mo:neutron-capabilities`), TypeScript + React 19, esbuild + Bun, `neutron-design-system`, `neutron-tools/app`.

**Spec:** `docs/superpowers/specs/2026-08-18-chipswap-design.md`

## Global Constraints

- App id `chipswap`; manifest `name` `Chipswap`; `"format": 3`; `"version": 100` (0.1.0); `"update_source": "233tv-xiaaa-aaaay-aacta-cai"`.
- License `LicenseRef-Neutron-Sovereign-Application-License-1.0` in `package.json` plus a `NOTICE` file (AGENTS.md: new apps use the repository's `LICENSE.APP`).
- Memory root id `chipswap`, schema version 1, `"migrations": []`. `backend/memory/chipswap/v1.mo` may import only pinned packages (`mo:core/*`) — **never** a relative import — and is immutable after release.
- Chip geometry is fixed data, not a literal in loops: row widths `9,13,17,19,21,23,25,27,27,29,29,31,31,31,31,31,31,31,31,31,29,29,27,27,25,23,21,19,17,13,9`; `PIXEL_COUNT = 757`; `shape_id = "circle31"`.
- Bounds: 10 design slots, palette ≤ 64, title 1..48 chars, holdings ≤ 500, directory ≤ 512, catalog cache ≤ 32 designers, incoming trades ≤ 64, outgoing ≤ 32, replay ≤ 256, custom brushes ≤ 16, directory share ≤ 32 principals per exchange.
- Every public method type must be **declared locally in `backend/main.mo`**. The method-schema generator resolves local aliases but cannot follow imported module aliases or generic `Result<T>` applications. Service modules may return structurally identical types; Motoko structural typing makes that safe and drift becomes a compile error.
- Owner-facing method payloads carry no `Blob`: pixels are 1514 lowercase hex chars, palette entries are `"#rrggbb"`, request ids are 32 lowercase hex chars. `Nat`/`Int` cross the kernel JSON bridge as decimal **strings**.
- Never call `from_candid` on peer bytes. Peer replies are unwrapped by exact prefix check plus canonical LEB length, then parsed as `CSW1`.
- No `mo:base/Random`, no `mo:core/Random`, no raw cycle or actor primitives.
- Run app scripts from `apps/chipswap` (script paths are relative to the app directory).
